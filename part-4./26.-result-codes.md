## 1. 결과가 기록되는 위치

발송 결과는 발송 원장 테이블(기본 `ODYSSEY`, 완료 후 `ODYSSEY_LOG`로 이관)의 다음 컬럼에 기록됩니다.

| 컬럼 | 내용 |
|---|---|
| `RESULT` | 문자(SMS/LMS/MMS/VMS) 결과코드 — **숫자** |
| `KKO_RESULT` | 카카오(알림톡/친구톡) 결과코드 — **숫자** |
| `RCS_RESULT` | RCS 결과코드 — **숫자** |
| `RESULT_DESC` | 실패 사유 문구 — **문자열** (최대 200자) |
| `STATUS` | 처리 상태 (`2`·`5`·`8` 발송 완료. 로그 테이블의 `102`·`105`·`108` 은 통계 반영까지 끝난 상태이며 실패가 아님) |
| `TRACKING_ID` | 통신사 접수 번호. **비어 있으면 통신사에 요청이 가기 전 단계에서 실패한 것** |

> **핵심**: 결과코드 컬럼에는 숫자만 들어갑니다. 원본 코드 표기(`ERR_NO_TOKEN` 등)는 `RESULT_DESC`에만 남습니다.

## 2. 숫자 대역으로 체계 구분하기

하나의 결과코드 컬럼에 여러 체계가 섞여 들어오기 때문에, **저장된 숫자의 대역을 보고 어느 체계인지 판별**합니다.

| 대역 | 체계 | 설명 |
|---|---|---|
| `0` | **성공** | 체계별 성공값(`10000`·`0000`·`000000`)을 모두 `0`으로 통일해 저장 |
| `-2 ~ 9999` | TCS | KT 직접 연동 발송 결과 |
| `10000 ~ 19999` | XROSHOT | CPaaS(커뮤니즈) 경유 발송 결과 |
| `40000 ~ 79999` | RCS | `RCS_RESULT` 전용 |
| `90001 ~ 90006` | **Odyssey 자체** | 발송 전 검증 실패 — [4-1](#4-1-발송-전-검증-실패-9000190006) |
| `900001 ~ 910104` | CPaaS API 오류 | 요청 자체가 거절됨. `E00101` → `900101` |
| `99999` | UNKNOWN | 응답이 비었거나 대역을 벗어남 |
| `-1` | **UNPARSED** | 숫자로 변환할 수 없는 Odyssey 자체 코드 — [3장](#3-result-가--1-일-때) |

### CPaaS API 오류(900001~) 읽는 법

`900000`을 빼면 원래 코드의 숫자부가 됩니다.

```
900101 - 900000 = 101   →  E00101
910104 - 900000 = 10104 →  E10104
```

> **주의**: 이 대역은 "메시지가 이렇게 실패했다"가 아니라 **"요청 자체가 거절됐다"**는 뜻입니다. 발송 결과코드와 섞어서 해석하면 안 됩니다.
>
> 과거에는 `E` 만 떼고 저장해 `E00101`이 `101`로 기록됐고, TCS `101`(메시지 내용 스팸)과 값이 겹쳐 **틀린 설명이 표시되는 문제**가 있었습니다. 현재는 대역을 분리해 해결됐습니다.

## 3. RESULT 가 -1 일 때

Odyssey 자체 코드 중 **숫자가 아닌 코드(`ERR_` 로 시작)는 `-1`로 저장**됩니다.

| 저장 직전 코드 | `RESULT` | `RESULT_DESC` |
|---|---|---|
| `90001` | `90001` | `imageUrl is required` |
| `ERR_E00101` | `900101` | `ERR_E00101 파라미터명이 유효하지 않습니다` |
| `ERR_NO_TOKEN` | **`-1`** | `ERR_NO_TOKEN CPAAS 토큰 획득 실패` |
| `ERR_HTTP_500` | **`-1`** | `ERR_HTTP_500 ...` |

**`RESULT = -1` 이면 숫자만으로는 원인을 알 수 없습니다. 반드시 `RESULT_DESC`를 확인하십시오.** 원본 코드 문자열이 설명 앞에 붙어 기록됩니다. 단, 4-6 의 `ERR_ROUTE_` 코드 · `ERR_PAUSE_TIME` 과 4-7 의 수집 실패는 코드 표기 없이 사유 문구만 기록됩니다.

```sql
SELECT MSG_ID, STATUS, RESULT, KKO_RESULT, RCS_RESULT, RESULT_DESC, TRACKING_ID
FROM ODYSSEY
WHERE RESULT = -1 OR KKO_RESULT = -1 OR RCS_RESULT = -1
ORDER BY MSG_ID DESC;
```

## 4. Odyssey 자체 코드 목록

통신사에 요청을 보내기 전, 또는 응답을 처리하는 과정에서 Odyssey가 부여하는 코드입니다.
**이 코드가 기록된 건은 통신사에 과금되지 않습니다**(`TRACKING_ID`가 비어 있는 경우).

### 4-1. 발송 전 검증 실패 (90001~90006)

CPaaS 경유 발송에서 **요청을 만들기 전에** 필수값·형식을 검사해 걸러냅니다.

| 코드 | 의미 | `RESULT_DESC` 예 | 조치 |
|---|---|---|---|
| `90001` | 필수값 누락 | `imageUrl is required`<br>`templateId is required`<br>`content is required` | 해당 항목을 DB 컬럼에 입력 |
| `90002` | 형식 오류 | `callbackNum must be digits length 3-16` | 숫자/자릿수 규격 확인 |
| `90003` | 길이 초과 | `content max bytes is 90`<br>`subject max bytes is 64` | 본문·제목 길이 축소 |
| `90004` | JSON 형식 오류 | `kButtons is invalid JSON` | 버튼·옵션 JSON 문법 확인 |
| `90005` | 파일 오류 | `MMS fileList is required`<br>`MMS file extension must be jpg/jpeg/exif`<br>`MMS fileList max count is 3` | 첨부 규격 확인 (최대 3개·1MB·jpg 계열) |
| `90006` | 미지원 메시지 타입 | `Unsupported CPaaS legacy msgType` | `MSG_TYPE` 값 확인 |
| `NO_SENDER_ID` | GSMS 발신자 조회 실패 | `sender-id 조회 실패` | 국가코드에 맞는 sender-id 설정 확인 |

> **KT 직접 연동 경로에는 이 사전 검증이 없습니다.** 잘못된 값이 그대로 통신사로 전달되어 통신사 결과코드로 실패합니다.

### 4-2. 세션 · 인증

| 코드 | 의미 | 조치 |
|---|---|---|
| `ERR_NO_SESSION` | 발송 세션을 찾지 못함 | 설정의 세션 `seq`와 계정 매핑 확인. **`seq`가 중복되면 앞쪽 세션만 선택**됩니다 |
| `ERR_NO_TOKEN` | CPaaS 인증 토큰 획득 실패 | API ID/PW, 연동 서버 접속 상태 확인 |
| `ERR_SESSION_CLOSED` | KT 세션이 종료된 상태에서 발송 시도 | KT 연동 상태 확인 후 재발송 |
| `ERR_SHUTDOWN` | 엔진 종료 중 발송 시도 | 재기동 후 재발송 |

### 4-3. API 응답

| 코드 | 의미 | 조치 |
|---|---|---|
| `ERR_HTTP_<상태코드>` | HTTP 오류 응답 (예: `ERR_HTTP_500`) | 상태코드별 확인. `5xx`는 연동사 장애 가능성 |
| `ERR_<벤더코드>` | 연동사가 거절 (예: `ERR_E00101`) | 벤더 코드 기준으로 확인. `RESULT`는 `900000`+ 대역 |
| `ERR_API` | 발송 중 예외 발생 | `RESULT_DESC`의 예외 메시지 확인 |
| `ERR_EMPTY` · `ERR_EMPTY_RESULT` | 응답 본문이 비어 있음 | 연동사 응답 상태 확인 |
| `ERR_NO_RESPONSE` | 개별 수신자 응답 누락 | 재발송 대상 |
| `ERR_EXCEPTION` | 일반 예외 | `RESULT_DESC` 확인 후 문의 |

### 4-4. 결과 매핑

접수는 됐으나 응답에서 수신자를 매칭하지 못한 경우입니다.

| 코드 | 의미 | 조치 |
|---|---|---|
| `ERR_NO_TRACKING` | 응답에 접수 목록이 없음 | 재발송 대상 |
| `ERR_NO_TRACKING_ID` | 해당 수신자의 접수번호 없음 | 재발송 대상 |
| `ERR_FAIL_RECEIVE` | 연동사가 수신 거부로 분류 | 수신번호 유효성 확인 |
| `ERR_NO_REQUEST_ID` | 브랜드 동보 요청 ID 없음 | 재발송 대상 |
| `ERR_TRACKING_UPDATE` | 접수번호 DB 반영 실패 | **발송은 됐을 수 있음.** 중복 발송 주의 — 결과 리포트 확인 후 판단 |

### 4-5. KT 직접 연동 전용

| 코드 | 의미 | 조치 |
|---|---|---|
| `ERR_KT_STORAGE` | 첨부파일 저장 위치 할당 실패 | KT 연동 상태 확인 |
| `ERR_KT_UPLOAD` | MMS 파일 업로드 실패 | 파일 경로·크기 확인 |
| `ERR_KT_FINISH_UPLOAD` | 업로드 완료 통보 실패 | 재발송 대상 |
| `ERR_KT_CONVERT` | VMS 음성 변환(TTS) 요청 실패 | 본문 내용 확인 |
| `ERR_FILE_EXCEPTION` | VMS 파일 또는 변환 결과 없음 | 첨부파일 확인 |
| `ERR_NO_CUSTOM_MESSAGE_ID` | 메시지 식별자 누락 | 문의 (엔진 내부 오류) |

### 4-6. 라우팅 · 큐

`ERR_ROUTE_` 로 시작하는 코드와 `ERR_PAUSE_TIME` 은 **`RESULT`** 가 `-1` 이고, **`RESULT_DESC`** 에 코드 표기 없이 사유 문구만 기록됩니다.

| 코드 | 의미 | 조치 |
|---|---|---|
| `ERR_ROUTE_INVALID` | 메시지 타입 또는 전송 채널 값 누락. `RESULT_DESC` 는 `msgType 또는 transmission 누락` | `MSG_TYPE` 값과 전송 채널 설정 확인 |
| `ERR_ROUTE_VMS_CPAAS` | VMS는 CPaaS로 발송 불가. `RESULT_DESC` 는 `VMS는 CPAAS로 발송할 수 없음` | 전송 채널 설정 확인 |
| `ERR_ROUTE_GSMS_NOT_CPAAS` | GSMS는 CPaaS로만 발송 가능. `RESULT_DESC` 는 `GSMS는 CPAAS(커뮤니즈)로만 발송 가능함` | 전송 채널 설정 확인 |
| `ERR_ROUTE_NO_ACCOUNT` | 발송 계정(세션) 없음. `RESULT_DESC` 가 `등록된 발송 계정 없음` 이면 해당 게이트웨이에 등록된 계정이 없는 것이고, `발송 가능 계정 없음` 이면 계정이 모두 일시정지 상태 | 세션 설정과 기동 로그의 `[Accounts]` 경고 확인 |
| `ERR_PAUSE_TIME` | 발송 금지 시간에 들어와 실패 처리됨 (처리 방식이 "즉시 실패 처리"일 때). `RESULT_DESC` 는 `pause time fail` | Web UI "발송 금지 시간" 설정 확인 |
| `ERR_NO_SERVICE` | 해당 채널 서비스 미동작 | 채널 활성화 설정 확인 |
| `ERR_UNSUPPORTED_TYPE` | 미지원 메시지 타입 | `MSG_TYPE` 값 확인 |
| `ERR_ENQUEUE_FAIL` · `ERR_ENQUEUE_EX` | 발송 큐 투입 실패 | 연동 상태 확인 후 재발송 |
| `ERR_INVALID_SERVICE_TYPE` | 내부 서비스 타입 불일치 | 문의 (엔진 내부 오류) |

### 4-7. 수집

발송 테이블에서 메시지를 읽어 오는 단계에서 실패한 경우입니다. **`RESULT_DESC`** 에 코드 표기 없이 사유 문구만 기록됩니다.

| `RESULT` | `RESULT_DESC` | 의미 | 조치 |
| -------- | ------------- | --- | --- |
| `-1` | `수집 DTO 변환 실패: ...` | 발송 테이블의 행을 발송 데이터로 변환하지 못함 (로그에는 `ERR_COLLECT_CONVERT` 로 기록) | 해당 행의 컬럼 값(형식 · 길이) 확인. 같이 수집된 다른 메시지는 정상 발송됩니다 |

## 5. 자주 묻는 사례

### 결과코드가 `0`인데 수신이 안 됨

`0`은 **연동사 접수 성공**을 의미하며 단말 수신 완료와는 다릅니다. `DELIVER_TIME`과 `REPORT_RECV_TIME`으로 최종 결과 수신 여부를 확인하십시오.

### `TRACKING_ID`가 비어 있음

통신사에 요청이 전달되기 전에 실패한 것입니다. **과금되지 않습니다.** 원인은 `RESULT_DESC`에 있습니다.

### 같은 코드인데 설명이 다름

결과코드 컬럼에 여러 체계가 섞여 있습니다. [2장](#2-숫자-대역으로-체계-구분하기)의 대역표로 어느 체계인지 먼저 확인하십시오. 특히 `900000` 이상은 발송 결과가 아니라 **요청 거절**입니다.
