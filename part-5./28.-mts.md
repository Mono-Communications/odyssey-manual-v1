# 28. MTS 규격

MTS 규격은 고객사가 사용하던 **MTS 에이전트의 테이블(`MTS_*`)을 Odyssey 가 그대로 읽고 쓰는 방식**입니다. 고객 시스템은 기존처럼 MTS 테이블에 INSERT 하고, Odyssey 가 이를 수집해 발송하고 결과를 기록합니다.

이 페이지는 MTS 규격 배포본을 사용하는 고객사를 위한 안내입니다. 여기에 적지 않은 설정과 운영 방법은 표준 Odyssey 와 같습니다.

{% hint style="info" %}
* 지원 DBMS : **Oracle 11g 이상**
* 지원 메시지 : **SMS / LMS / MMS / 카카오 알림톡**
* 발송 경로 : **CPaaS(커뮤니즈)**
{% endhint %}

## <mark style="color:blue;">2. 설치 준비</mark>

### 2-1. 연동 컬럼 추가 <a href="#tracking-columns" id="tracking-columns"></a>

Odyssey 는 발송 결과를 조회하기 위해 MTS 테이블에 컬럼 3개를 추가로 사용합니다.

<table><thead><tr><th width="220">컬럼</th><th width="170">형식</th><th>용도</th></tr></thead><tbody><tr><td><strong><code>TRAN_TRACKING_ID</code></strong></td><td>VARCHAR2(40)</td><td>CPaaS 접수 번호</td></tr><tr><td><strong><code>TRAN_TOKEN</code></strong></td><td>VARCHAR2(80)</td><td>결과 조회용 값</td></tr><tr><td><strong><code>TRAN_C_STATUS</code></strong></td><td>VARCHAR2(1)</td><td>결과 조회 진행 상태</td></tr></tbody></table>

{% hint style="info" %}
**기존에 사용 중이던 테이블이 없는 경우** 에이전트가 기동되며 자동으로 테이블과 인덱스를 생성합니다. 이때는 연동 컬럼이 포함되어 생성되므로 아래 SQL 을 실행하지 않아도 됩니다.
{% endhint %}

**기존 MTS 테이블을 그대로 사용하는 경우**에는 Odyssey 를 기동하기 전에 아래 SQL 로 6개 테이블에 연동 컬럼을 추가합니다.

```sql
-- 테이블 이름은 고객 테이블 이름에 맞춥니다.
-- 스키마 접두어(예: OWNER.)가 필요하면 테이블 이름 앞에 붙여 실행합니다.
ALTER TABLE MTS_ALIMTALK_MSG     ADD (TRAN_TRACKING_ID VARCHAR2(40), TRAN_TOKEN VARCHAR2(80), TRAN_C_STATUS VARCHAR2(1));
ALTER TABLE MTS_ALIMTALK_MSG_LOG ADD (TRAN_TRACKING_ID VARCHAR2(40), TRAN_TOKEN VARCHAR2(80), TRAN_C_STATUS VARCHAR2(1));
ALTER TABLE MTS_SMS_MSG          ADD (TRAN_TRACKING_ID VARCHAR2(40), TRAN_TOKEN VARCHAR2(80), TRAN_C_STATUS VARCHAR2(1));
ALTER TABLE MTS_SMS_MSG_LOG      ADD (TRAN_TRACKING_ID VARCHAR2(40), TRAN_TOKEN VARCHAR2(80), TRAN_C_STATUS VARCHAR2(1));
ALTER TABLE MTS_MMS_MSG          ADD (TRAN_TRACKING_ID VARCHAR2(40), TRAN_TOKEN VARCHAR2(80), TRAN_C_STATUS VARCHAR2(1));
ALTER TABLE MTS_MMS_MSG_LOG      ADD (TRAN_TRACKING_ID VARCHAR2(40), TRAN_TOKEN VARCHAR2(80), TRAN_C_STATUS VARCHAR2(1));
```

{% hint style="danger" %}
연동 컬럼이 없으면 **Odyssey 가 기동을 멈춥니다.** <mark style="color:red;">**`logs/live/system.log`**</mark> 에 아래 오류가 기록되면 위 SQL 을 실행한 뒤 다시 기동하세요.

`[CreateTable] MTS 테이블에 Odyssey 연동 컬럼이 없어 기동을 멈춥니다. config/mts/mts_oracle11g_alter.sql 을 실행한 뒤 다시 기동하십시오. 없는 컬럼: ...`

**`TRAN_TOKEN`** 길이가 80 보다 짧으면 기동은 하지만 `[CreateTable] ... 길이 ... - 긴 값이 오면 저장이 실패한다` 경고가 기록됩니다. 길이를 80 이상으로 변경하세요.
{% endhint %}

### 2-2. 인덱스

* 테이블을 Odyssey 가 자동으로 만든 경우 인덱스도 함께 만들어집니다.
* 기존 MTS 테이블을 사용하는 경우, 수집 · 결과 조회에 필요한 인덱스 SQL 을 연동 컬럼 SQL 과 함께 제공합니다. 운영 전에 실행해 주세요.

{% hint style="warning" %}
수집 쿼리에 맞는 인덱스(**`TRAN_STATUS, TRAN_DATE`**)가 없으면 대기 건이 많을 때 수집이 느려지거나 실패할 수 있습니다.
{% endhint %}

### 2-3. DB 접속 계정

<mark style="color:red;">**`application.yml`**</mark> 의 DB 계정은 **MTS 테이블을 소유한 계정**이어야 합니다. Odyssey 는 접속 계정의 테이블 목록으로 MTS 테이블이 있는지 확인합니다. 다른 계정으로 접속하면 그 계정에 빈 MTS 테이블을 새로 만듭니다.

### 2-4. recovery 폴더

Odyssey 설치 폴더의 <mark style="color:red;">**`recovery/`**</mark> 에 쓰기 권한이 있어야 합니다. DB 반영에 실패한 결과나 정지 때 되돌리지 못한 메시지를 SQL 파일로 남기고, 다음 기동 때 실행합니다.

## <mark style="color:blue;">3. application.yml 설정</mark>

표준 설정과 다른 항목만 표기했습니다.

```yaml
common:
  standard: MTS                # MTS 규격 사용
  execute:
    sms: true
    lms: true
    mms: true
    vms: false                 # MTS 규격 미지원
    gsms: false                # MTS 규격 미지원
    rcs: false                 # MTS 규격 미지원
    kakao: true
    fetch: true
    stat: false                # MTS 규격은 통계를 사용하지 않음
  transmission:
    msg: CPAAS
    rcs: CPAAS
    kakao: CPAAS
  tables:
    table-name:
      # 기존 rv-* 항목은 그대로 두고, 아래 MTS 항목을 추가합니다.
      mts-atalk-send: MTS_ALIMTALK   # 알림톡 테이블 접두어 (고객 테이블 이름에 맞춤)
      mts-sms-send: MTS_SMS          # SMS 테이블 접두어
      mts-mms-send: MTS_MMS          # LMS · MMS 테이블 접두어
```

## <mark style="color:blue;">4. 발송 INSERT 예시</mark>

고객 시스템이 MTS 테이블에 INSERT 하면 Odyssey 가 수집해 발송합니다.

* **`TRAN_PR`** : 메시지 키. **숫자로만 된 값**을 넣습니다. 숫자가 아니면 발송하지 않고 실패 처리합니다. Odyssey 가 자동으로 만든 테이블은 **`TRAN_PR`** 을 비우고 INSERT 하면 시퀀스로 채번합니다.
* **`TRAN_STATUS`** : `'1'` (발송 대기) 로 넣습니다.
* **`TRAN_DATE`** : 발송 시각. 이 시각이 지나야 수집하며, 24시간이 지난 메시지는 발송하지 않고 만료 처리합니다.
* **`TRAN_REFKEY`**, **`TRAN_ID`**, **`TRAN_ETC1~4`**, **`TRAN_GRPSEQ`** : 고객 시스템용 컬럼입니다. Odyssey 는 값을 바꾸지 않고 로그 테이블과 대체 발송 행으로 그대로 옮깁니다.
* 수신번호(**`TRAN_PHONE`**), 발신번호(**`TRAN_CALLBACK`**)는 특수문자 없이 입력합니다.

### 4-1. SMS

```sql
INSERT INTO MTS_SMS_MSG (
    TRAN_PR, TRAN_PHONE, TRAN_CALLBACK, TRAN_MSG, TRAN_DATE, TRAN_TYPE, TRAN_STATUS
) VALUES (
    '1000001',                     -- TRAN_PR (숫자)
    '01012345678',                 -- 수신번호
    '0212345678',                  -- 발신번호
    '[테스트] Odyssey SMS 발송',
    SYSDATE,                       -- 발송 시각
    0,                             -- TRAN_TYPE : SMS
    '1'                            -- 발송 대기
);
```

{% hint style="info" %}
본문이 **90바이트를 넘으면 LMS 로 바뀌어 발송**됩니다 (제목 없음, LMS 요금 적용). 결과는 SMS 테이블에 SMS 결과 코드로 기록됩니다.
{% endhint %}

### 4-2. LMS

첨부(`MTS_MMS_CONTENTS`) 행 없이 `MTS_MMS_MSG` 에 INSERT 하면 LMS 로 발송합니다.

```sql
INSERT INTO MTS_MMS_MSG (
    TRAN_PR, TRAN_PHONE, TRAN_CALLBACK, TRAN_SUBJECT, TRAN_MSG, TRAN_DATE, TRAN_TYPE, TRAN_STATUS
) VALUES (
    '1000002',
    '01012345678',
    '0212345678',
    '[안내]',                      -- 제목
    'LMS 테스트 발송입니다.',
    SYSDATE,
    4,                             -- TRAN_TYPE : LMS · MMS
    '1'
);
```

### 4-3. MMS

`MTS_MMS_MSG` 와 같은 **`TRAN_PR`** 로 `MTS_MMS_CONTENTS` 에 첨부 행을 함께 INSERT 합니다. 첨부 행이 있으면 MMS 로 발송합니다.

```sql
INSERT INTO MTS_MMS_MSG (
    TRAN_PR, TRAN_PHONE, TRAN_CALLBACK, TRAN_SUBJECT, TRAN_MSG, TRAN_DATE, TRAN_TYPE, TRAN_STATUS
) VALUES (
    '1000003',
    '01012345678',
    '0212345678',
    '[안내]',
    'MMS 테스트 발송입니다.',
    SYSDATE,
    4,
    '1'
);

INSERT INTO MTS_MMS_CONTENTS (
    TRAN_PR, CONTENT_SEQ, CONTENT_TYPE, CONTENT_NAME
) VALUES (
    '1000003',                     -- MTS_MMS_MSG 와 같은 TRAN_PR
    1,                             -- 첨부 순번
    'IMG',
    'test.jpg'                     -- file-dir 기준 파일 경로
);
```

{% hint style="warning" %}
* **`CONTENT_NAME`** 은 <mark style="color:red;">**`application.yml`**</mark> 의 <mark style="color:green;">`common.user.file-dir`</mark> 기준 경로입니다. 해당 위치에 파일이 있어야 합니다.
* 첨부 파일을 하나라도 읽지 못하면 **발송하지 않고 실패 처리**합니다.
* 두 INSERT 를 한 트랜잭션으로 커밋하세요. 첨부 행보다 메시지 행이 먼저 수집되면 LMS 로 발송될 수 있습니다.
{% endhint %}

## <mark style="color:blue;">5. 상태와 결과 코드</mark> <a href="#status" id="status"></a>

### TRAN\_STATUS

<table><thead><tr><th width="160">값</th><th>의미</th></tr></thead><tbody><tr><td><strong><code>1</code></strong></td><td>발송 대기 (고객 시스템이 INSERT)</td></tr><tr><td><strong><code>6</code></strong></td><td>Odyssey 가 수집함 (발송 중)</td></tr><tr><td><strong><code>2</code></strong></td><td>CPaaS 접수 완료, 결과 대기</td></tr><tr><td><strong><code>3</code></strong></td><td>결과 수신 (성공 · 실패는 <code>TRAN_RSLT</code> 로 판단)</td></tr><tr><td><strong><code>5</code></strong></td><td>발송 실패 (발송 전 검증 실패, 만료 등)</td></tr></tbody></table>

`3` · `5` 가 된 메시지는 로그 테이블(`_MSG_LOG`)로 옮겨집니다.

**`TRAN_C_STATUS`** 가 `U` 인 메시지는 발송 요청 후 응답을 받지 못해 **접수 여부를 확인할 수 없는** 메시지입니다. ([6. 동작 방식](#behavior) 참고)

### Odyssey 가 기록하는 컬럼

## <mark style="color:blue;">6. 동작 방식</mark> <a href="#behavior" id="behavior"></a>

### 알림톡 대체 발송

알림톡이 최종 실패하고 **`TRAN_REPLACE_MSG`** 에 문구가 있으면, 로그 테이블로 옮길 때 대체 발송 행을 만듭니다.

* 대체 발송 문구가 **90바이트 이하면 SMS**(`MTS_SMS_MSG`), **넘으면 MMS 테이블**(`MTS_MMS_MSG`, 첨부 없는 장문)에 새 행을 만듭니다.
* 대체 발송 행의 **`TRAN_PR`** 은 알림톡과 같은 값입니다. 고객 시스템용 컬럼(**`TRAN_REFKEY`**, **`TRAN_ID`**, **`TRAN_ETC1~4`**, **`TRAN_GRPSEQ`**)도 그대로 복사합니다.
* 알림톡 행의 **`TRAN_REPLACE_TYPE`** 에 `S` 또는 `M` 을 기록합니다. 대체 발송하지 않은 행은 `N` 입니다.
* 대상 테이블에 같은 **`TRAN_PR`** 행이 이미 있으면 대체 발송 행을 만들지 않습니다.
* 결과를 받지 못한 만료 건, 응답을 받지 못한 건은 대체 발송하지 않습니다. (중복 수신 방지)

### 발송 전 실패 처리

<table><thead><tr><th width="280">경우</th><th>처리</th></tr></thead><tbody><tr><td><strong><code>TRAN_PR</code></strong> 이 숫자가 아님</td><td>수집하지 않고 1분 안에 <code>TRAN_STATUS</code> <code>5</code>, 채널 기본 실패 코드로 처리. 로그 <code>[ExpireCheck] MTS TRAN_PR 이 숫자가 아니어서 발송하지 않고 실패 처리</code></td></tr><tr><td>MMS 첨부 파일을 읽지 못함</td><td>발송하지 않고 실패 처리</td></tr><tr><td>수신번호 · 발신번호 · 본문 형식 오류</td><td><code>TRAN_STATUS</code> <code>5</code></td></tr></tbody></table>

### 응답을 받지 못한 발송

발송 요청은 보냈지만 응답을 받지 못한 경우(응답 시간 초과, 깨진 응답)는 CPaaS 에 접수됐는지 알 수 없습니다. 이 메시지는 실패로 처리하지 않고 **`TRAN_STATUS`** `6`, **`TRAN_C_STATUS`** `U` 로 남겨 둡니다. 실패로 처리하면 알림톡 대체 발송이 나가 수신자가 두 번 받을 수 있기 때문입니다. 이 메시지는 만료 시각에 대체 발송 없이 실패로 처리됩니다.

### 만료

<table><thead><tr><th width="300">대상</th><th>처리</th></tr></thead><tbody><tr><td>발송 대기(<code>1</code>) 상태로 <code>TRAN_DATE</code> 부터 24시간 지남</td><td rowspan="3"><code>TRAN_STATUS</code> <code>5</code>, 채널별 만료 코드 (<a href="#status">5. 상태와 결과 코드</a> 참고). 대체 발송 없음</td></tr><tr><td>결과 대기(<code>2</code>) 상태로 접수 후 24시간 지남</td></tr><tr><td>수집(<code>6</code>) 상태로 25시간 지남</td></tr></tbody></table>

### 발송 금지 시간

* **즉시 실패 처리** : 금지 시간에 수집된 메시지는 `TRAN_STATUS` `5` 로 처리합니다. 금지 시간 전용 결과 코드는 없으며 채널 기본 실패 코드가 기록됩니다.
* **금지 시간 해제 후 자동 발송** : 메시지는 `TRAN_STATUS` `1` 로 남아 있다가 금지 시간이 끝나면 발송됩니다.

### 정지

정상 정지하면 큐에 남아 있던 미발송 메시지를 `TRAN_STATUS` `6` 에서 `1` 로 되돌립니다. DB 에 반영하지 못하면 <mark style="color:red;">**`recovery/`**</mark> 에 SQL 파일로 남기고 다음 기동 때 실행합니다. 정지 대기 시간 등 나머지 동작은 표준과 같습니다. ([4. 실행 / 정지](../part-1./4.-start-stop.md#stop-behavior) 참고)

### HA 이중화

두 노드는 **`TRAN_PR` 의 끝자리(10으로 나눈 나머지)**로 담당 메시지를 나눕니다. 노드별 담당 비율은 <mark style="color:red;">**`ha.properties`**</mark> 의 **`LOAD_BALANCE_PERCENT`** 로 정하며, 설정 방법은 표준과 같습니다. ([15. HA 이중화 설정](../part-2./15.-ha-ha.properties/README.md) 참고)

### Web UI

* 실패 사유 조회 기능을 사용하지 않습니다. (MTS 테이블에 실패 사유 문구 컬럼이 없음)
* 통계를 처리하지 않습니다.

## <mark style="color:blue;">7. 주의 사항</mark>

{% hint style="warning" %}
발송 묶음을 CPaaS 로 보내는 도중이나 DB 응답이 멈춘 동안 Odyssey 가 비정상 종료되면, 이미 CPaaS 에 접수된 메시지가 **`TRAN_STATUS`** `6` 으로 남을 수 있습니다. 이 메시지는 25시간 뒤 만료 실패로 기록되고 대체 발송은 하지 않습니다.

실제로는 발송이 진행되었을 수 있습니다. 실제 수신 결과 확인이 필요한 경우 문의해 주세요. ([27. 빠른 문의를 위한 가이드](../part-4./27.-inquiry-guide.md) 참고)
{% endhint %}
