### <mark style="color:blue;">STATUS 9 — 로그 테이블 이관 실패</mark> <a href="#status-9" id="status-9"></a>

발송이 끝난 메시지(**`STATUS`** 2 · 5 · 8)는 로그 테이블(**`rv-submit-log`**)로 이관됩니다. 이관하지 못한 메시지는 **`STATUS`** 가 **`9`** 로 바뀌어 발송 테이블에 남습니다. (Odyssey 1.0.10 이상)

* **`STATUS 9`** 인 메시지는 **자동으로 다시 이관하지 않습니다.** 이관 전의 값(2 · 5 · 8)은 **`9`** 로 덮여 남지 않습니다.
* 발송 결과(**`RESULT`**, **`RESULT_DESC`**, **`DELIVER_TIME`** 등)는 그대로 남아 있습니다.
* 다음 경우에 발생합니다.
  * 로그 테이블에 같은 **`MSG_ID`** 가 이미 있고, 로그 테이블에 **`MSG_ID`** 기본 키(PK)가 남아 있는 경우
  * 로그 테이블을 만들지 못한 경우 (DB 계정에 테이블 생성 권한이 없는 경우 등)
  * 그 밖의 DB 오류로 로그 테이블에 적재하지 못한 경우

{% hint style="warning" %}
**`STATUS 9`** 가 발생하면 **`logs/live/system.log`** 에서 `[FetchPoller] archive 실패` 또는 `[FetchPoller] 로그 테이블 생성 실패` 로그의 원인(`cause=`)을 먼저 확인하세요. ([22. 로그 / 에러 분석](../part-4./22..md) 참고)

원인이 로그 테이블의 **`MSG_ID`** 기본 키라면 [19. 테이블 레이아웃](19.-mysql/#log-table-pk) 의 안내에 따라 기본 키를 삭제하세요.
{% endhint %}
