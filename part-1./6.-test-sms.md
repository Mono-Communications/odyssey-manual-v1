## <mark style="color:blue;">결과 확인</mark> <a href="#id-1" id="id-1"></a>

발송 결과는 다음 3가지 채널 중 편한 곳에서 확인할 수 있습니다.

### <mark style="color:blue;">1. 로그</mark> <a href="#id-1" id="id-1"></a>

```bash
# 전체 로그 (모든 모드)
tail -f logs/live/system.log

# 특정 메시지 종류만 보기 (kt 크로샷 직접연동 문자)
tail -f logs/live/sender-kt-legacy.log

# 에러만 보기
tail -f logs/live/error.log
```

발송 및 로그 이관 성공 시 <mark style="color:green;">**`[KtSession-1] req_report 처리 customId=S****** result=0 duration=null`**</mark> / **`[FetchPoller] archive 완료 count=1 time=104ms`** 등의 메시지가 출력 됩니다.

### <mark style="color:blue;">2. Web UI</mark> <a href="#id-2-web-ui-multi" id="id-2-web-ui-multi"></a>

[5. Web UI 살펴보기](5.-web-ui-multi.md)의 모니터링 대시보드 접속 시, 파이프라인 그래프·TPS에서 메시지가 처리되는 과정을 시각적으로 확인할 수 있습니다.

### <mark style="color:blue;">3. DB</mark> <a href="#id-3-db" id="id-3-db"></a>

발송이 끝난 메시지는 결과가 기록된 뒤 곧바로 발송 테이블(**`ODYSSEY`**)에서 로그 테이블(**`ODYSSEY_LOG`**)로 이관됩니다. 이관은 보통 수 초 안에 끝나므로 **로그 테이블부터 확인**하세요.

또한 수신자 휴대폰에 메시지가 도착했다면 실발송 성공입니다.

#### 1) 로그 테이블 확인

{% tabs %}
{% tab title="MySQL" %}
```sql
SELECT MSG_ID, STATUS, RESULT, RESULT_DESC, DELIVER_TIME
FROM ODYSSEY_LOG
WHERE MSG_TYPE = 1
ORDER BY MSG_ID DESC
LIMIT 10;
```
{% endtab %}

{% tab title="MariaDB" %}
```sql

FROM ODYSSEY_LOG

LIMIT 10;
```
{% endtab %}

{% tab title="PostgreSQL" %}
```sql
SELECT MSG_ID, STATUS, RESULT, RESULT_DESC, DELIVER_TIME
FROM ODYSSEY_LOG
WHERE MSG_TYPE = 1
ORDER BY MSG_ID DESC

```
{% endtab %}

{% tab title="Oracle" %}
```sql

    SELECT MSG_ID, STATUS, RESULT, RESULT_DESC, DELIVER_TIME

```
{% endtab %}

{% tab title="SQL Server" %}

```sql
WHERE MSG_TYPE = 1
ORDER BY MSG_ID DESC;
```
{% endtab %}
