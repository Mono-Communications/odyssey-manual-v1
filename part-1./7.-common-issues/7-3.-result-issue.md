# 7-3. 발송은 시작되는데 결과가 안 오는 경우

**증상**: **`STATUS=1`** (전송 중) 상태로 멈춤

**점검**:

* 게이트웨이 outbound 방화벽 (KT 크로샷 IP/PORT는 [21. 게이트웨이 IP / PORT](../../part-4./21.-ip-port.md) 참고)
* <mark style="color:red;">`report-cycle`</mark> 값이 너무 길지 않은지 확인 (기본 `5000ms`)
* KT RCS의 `webhook-port`를 사용한다면, inbound 방화벽 허용 확인
* 발송 계정(세션)이 등록되어 있는지 확인 — 기동 로그(**`logs/live/system.log`**)에 `[Accounts] ... 실행이 켜져 있지만 등록된 계정이 0개` 경고가 있으면 **`common.transmission`** 에 지정한 게이트웨이의 **`sessions`** 설정이 비어 있는 것입니다. ([14. 계정 설정 (sessions)](../../part-2./14.-sessions/) 참고)

{% hint style="info" %}
Odyssey 1.0.8 부터는 발송 계정이 없는 메시지를 **`STATUS=1`** 로 두지 않고 바로 실패 처리합니다. 이때 **`RESULT`** 는 `-1`, **`RESULT_DESC`** 는 `등록된 발송 계정 없음`(또는 `발송 가능 계정 없음`) 으로 기록됩니다. 로그에는 `ERR_ROUTE_NO_ACCOUNT` 로 남습니다. ([26. 결과코드 매뉴얼](../../part-4./26.-result-codes.md) 참고)

1.0.7 이하에서는 같은 경우 메시지가 **`STATUS=1`** 상태로 오래 남을 수 있습니다.
{% endhint %}
